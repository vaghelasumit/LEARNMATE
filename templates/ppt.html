1.0 Project Overview & Motivation

💡 Background & Context

Modern university curricula require students to master vast amounts of technical knowledge across multiple subjects like Python, PHP, and DBMS.

Students frequently suffer from fragmented study resources scattered across multiple drives, chat groups, and physical notebooks without any structured method to systematically identify and correct their mistakes.

🎯 Purpose of LearnMate

LearnMate was engineered as an all-in-one centralized academic portal providing:

  • Structured Handouts: PDFs, PPTs, Drive links & embedded video lectures.
  • 3D Flip Flashcards: Interactive digital flashcards for fast recall.
  • Practice Quizzes: Instant scoring and performance analytics.
  • Automated Mistake Revision: Dynamic tracking of incorrect answers.
  • Admin-Issued Certificates: Official completion certificates with unique serial verification.

2.0 Problem Statement vs. Proposed Solution

❌ Existing Limitations

  • Scattered Study Material: Lecture notes, PPTs, and video links get lost across WhatsApp groups and drives.
  • No Active Recall: Traditional reading lacks rapid memory stimulation techniques like flashcard flipping.
  • Neglected Mistakes: After taking an exam or quiz, students rarely revisit questions they answered incorrectly.
  • No Real-Time Verification: Teachers lack a centralized dashboard to track attempts and manually authorize student course certificates.

✅ LearnMate Solution

  • Centralized Subject Handouts: Direct PDF downloads, Google Drive shortcuts, and embedded video lectures.
  • Interactive 3D Flashcards: Active recall system with animated flip interaction and progress counters.
  • Smart Revision Hub: Incorrect quiz answers are auto-saved to an isolated revision hub until mastered through retakes.
  • Teacher-Authorized Credentialing: Quiz passes trigger administrative generation of certificates with serial numbers.

3.4 Django MVT Architecture Workflow

1. Model (Data)

Django ORM models define the relational schema in pure Python code:

  • Subject: Course title, code, cover image.
  • StudyMaterial: Handouts, PPTs, Videos, Drive links.
  • Flashcard: Front question & back answer.
  • Quiz & QuizQuestion: MCQs with A/B/C/D choices.

2. View (Logic)

Python controllers handling business logic, user auth & queries:

  • take_quiz: Randomizes questions and tracks timer.
  • submit_quiz: Evaluates answers & records score.
  • revision_hub: Filters student mistake logs.
  • admin_generate_certificate: Issues serial numbers.

3. Template (UI)

HTML5 presentation dynamic templates with Django Template Language (DTL):

  • base.html: Universal navbar, footer, auth context.
  • course_detail.html: Handouts, flashcards & quizzes.
  • revision.html: Mistake cards with red/green highlights.
  • certificate_view.html: Printable official diploma.

4.2 Key Feature: Mistake-Based Revision Hub

🔄 How the Revision Engine Works

  1. Automatic Mistake Detection: When a student submits a quiz, any question answered incorrectly is automatically flagged and saved into the Revision model with status 'Pending'.
  2. Subject-Wise Filtering: Students select any subject (e.g., Python, DBMS) to view only mistakes pertinent to that specific course.
  3. Visual Mistake Comparison: The selected wrong answer is vividly highlighted in RED, while the true correct answer is highlighted in GREEN.
  4. Targeted Retake Quiz: A dynamic "Retake Quiz" is generated containing ONLY the pending mistakes.
  5. Automatic Mastery: Answering correctly updates the question to 'Mastered'!

📊 Pedagogical Benefits

Traditional learning platforms force students to repeat entire 20-question quizzes to practice the 2 questions they missed.

Adaptive Spaced Repetition:

Saves up to 75% of revision time by directing student focus strictly to demonstrated weaknesses.

Confidence & Retention:

Ensures 100% concept mastery before university semester examinations and campus placement technical interviews.

5.0 Database Design & Relational Models

📚 Course Core Models

  • Subject: Primary key, subject name, code, description, image.
  • StudyMaterial: Subject FK, title, material_type (PDF, PPT, Video), drive_link.
  • Flashcard: Subject FK, question prompt, answer explanation.

📝 Assessment Models

  • Quiz: Subject FK, title, total_questions, passing_marks.
  • QuizQuestion: Quiz FK, text, 4 options (A/B/C/D), correct_answer.
  • QuizAttempt: Student FK, Quiz FK, timestamp, completion status.
  • QuizAnswer: Attempt FK, Question FK, selected_answer, is_correct.

🎯 Revision & Credentials

  • QuizResult: Attempt OneToOne, score, total, percentage, Pass/Fail.
  • Revision: Student FK, Question FK, status (Pending/Mastered).
  • Certificate: Student FK, Subject FK, unique cert_no, issue_date.
  • Bookmark: Student FK, material FK, flashcard FK.

6.0 Security & Implementation Highlights

🛡️ Security Implementation

  • CSRF Protection: All form submissions (login, registration, quiz submit) are token-signed against cross-site request forgery.
  • Password Hashing: PBKDF2 with SHA-256 algorithm ensures zero plaintext credentials in database.
  • Role-Based Access Control: Strict @login_required and @user_passes_test(is_admin) decorators prevent student access to admin endpoints.
  • SQL Injection Immunity: Django ORM parameterized SQL statements completely eliminate SQLi vulnerabilities.

🗄️ Relational SQLite3 Architecture

  • Single Embedded File Database: Atomic disk-based persistence (db.sqlite3) eliminates complex background daemon requirements and port 3306 conflicts.
  • Full ACID Transaction Support: Guarantees transaction atomicity, consistency, isolation, and durability during simultaneous student quiz evaluations and certificate records.
  • Automated Data Seeding: Included seed_data.py script automatically populates academic MCA courses, flashcards, quizzes, and administrative accounts.
